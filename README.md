# Converter

GitHub: [alexbootch/IP_Media_tool](https://github.com/alexbootch/IP_Media_tool).

Основний шлях доставки: [публічний інсталятор та ip-media-tool-update](docs/PUBLIC_INSTALL.uk.md). На Ubuntu не потрібні Git clone/pull, GitHub tokens або SSH keys. Посилання завантаження почне працювати після ручної публікації першого public release.

Кросконвертор SDI, NDI, SRT та WebRTC для одного фізичного Linux-сервера. OMT відкладено на майбутнє; власний OMT-плагін не розробляємо. Медіаобробка — GStreamer; керування — браузерний граф із входом користувачів та журналом дій.

Статус на 2026-10-30: погоджено базові принципи, створено структуру каталогів і план. Виконуваної реалізації ще немає. Нативне розгортання з systemd — рекомендований базовий профіль; точні версії ОС, SDK і бібліотек визначаються перевіркою цільового хоста.

Кожна нода зберігає координати та власні налаштування у своєму JSON-конфігу. Нода-споживач додатково зберігає посилання на порт джерела. Окремого graph.json та бази даних немає.

Windows / VS Code використовується лише для коду та Git. Локальні тести, збирання, виконання коду та медіапрототипи не запускаються. Користувач вручну публікує зміни на GitHub та виконує інсталяцію, оновлення, перевірки й запуск на Linux-сервері.

Порядок підготовки: інвентаризація й аналіз залежностей → проєктування та схеми → каркас керування → перевірка SDK і медіатранспорту. SHM-досліди починаються після каркаса, лише на Linux у визначеному користувачем тестовому середовищі поза деревом вихідного коду.

## Каталоги

| Каталог | Призначення |
| --- | --- |
| `src/converter/control` | API, відновлення графа з конфігів, узгодження бажаного та фактичного стану |
| `src/converter/config` | Валідація, атомарні записи, версії та міграції конфігів |
| `src/converter/contracts` | Версійні медіаконтракти та повідомлення керування |
| `src/converter/runtime` | Життєвий цикл воркерів, IPC, підписки та відновлення |
| `src/converter/media` | SHM, часова модель та спільні примітиви обробки |
| `src/converter/hardware` | Інвентар, GPU/DeckLink/NIC capabilities та резервування ресурсів |
| `src/converter/discovery` | Інтерфейс каталогу джерел та ізольовані discovery-контексти |
| `src/converter/security` | Автентифікація, права та журнал дій |
| `src/converter/updates` | Перевірка й активація релізу, відкат |
| `node-sdk` | Публічний контракт ноди та спільний worker SDK |
| `plugins` | Каталог на кожен тип ноди: worker, manifest, UI, схеми та тести |
| `frontend` | Оболонка графа, користувачі, hardware inventory, журнали |
| `native` | Власні native helpers та GStreamer-адаптери, якщо потрібні |
| `schemas` | Машиночитані схеми конфігів і контрактів |
| `examples` | Приклади конфігів без секретів і прив'язки до конкретного сервера |
| `packaging` | Пакети, systemd, runtime-профіль та release manifest |
| `tools` | Інвентаризація хоста, діагностика, розробка та release tools |
| `tests` | Контракти, інтеграційні тести, відмови та ресурсні випробування |

Порожні каталоги позначають заплановані модулі, а не готові компоненти. Сторонні SDK не додані; їх постачання й ліцензії перевіряються окремо.
