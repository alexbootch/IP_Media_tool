# Редактор графа

Після входу відкрий «Робочий простір». Редактор читає типи з `/api/node-modules`, конфіги з `/api/nodes`, а стани воркерів із `/api/workers`. У конфігах зберігаються координати та з’єднання. Для роботи з графом потрібен браузер із підтримкою Pointer Events, ResizeObserver і AbortSignal.timeout.

- **Додати ноду** відкриває вибір типу, назви та параметрів. Поле параметрів приймає JSON-об’єкт за схемою вибраного модуля. Запуск виконується окремою кнопкою.
- Перетягни заголовок ноди. Після відпускання кнопки редактор зберігає координати. Координати можна також ввести у формі.
- Вибери вихід на картці джерела, потім сумісний вхід споживача. У формі споживача також можна замінити джерело або вибрати «Без з’єднання». API зберігає зв’язок у конфігу споживача та перевіряє сумісність портів і цикли. Втрачений порт або джерело позначаються на картці й у діагностиці.
- **Запустити** передає поточну ревізію конфігу. **Зупинити** зупиняє воркер або скасовує запуск чи відновлення. Статуси періодично оновлюються, поки робочий простір відкритий. При недоступному runtime картки показують, що статус невідомий.

Viewer може переглядати граф, а operator та admin можуть його змінювати і керувати воркерами. Для запису та керування потрібно вручну запустити `ip-media-tool-runtime`. Активну ноду спершу зупини перед редагуванням або переміщенням. При конфлікті ревізій онови граф і повтори зміну. Редактор використовує наявний атомарний запис конфігів і аудит API.

На поточному етапі каталог `plugins` містить порожні каталоги майбутніх модулів. Список типів з’явиться після реєстрації модулів. Для приймання UI на Linux потрібні зареєстровані модулі з вихідним і вхідним портами. Перевір створення, з’єднання, від’єднання, переміщення, перезавантаження сторінки, конфлікт ревізій та права Viewer. Медіаз’єднання також можна перевірити окремим headless сценарієм [SHM на Linux](SHM_TRANSPORT.uk.md).
