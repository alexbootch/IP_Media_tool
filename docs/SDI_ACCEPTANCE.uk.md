# Приймання SDI на Linux

Сценарій перевіряє фізичний маршрут від джерела SDI до виходу DeckLink і вимірює доданий зсув A/V. Потрібні три незалежно доступні порти або зовнішній SDI-аналізатор для вимірювання вручну. Почни з `1080p25`, вбудованого PCM 48 кГц і двох каналів.

## Оновлення та перевірка залежностей

Після публікації коміту в `main` виконай на Ubuntu:

```bash
ip-media-tool-update
cd /opt/ip-media-tool/current
ls plugins/sdi-input/manifest.json plugins/sdi-output/manifest.json tests/linux_sdi_acceptance.py
for factory in decklinkvideosrc decklinkaudiosrc decklinkvideosink decklinkaudiosink deinterlace interlace; do
  gst-inspect-1.0 --exists "$factory" || printf 'Відсутній: %s\n' "$factory"
done
systemctl is-active ip-media-tool ip-media-tool-runtime
```

Якщо сервіс був зупинений до оновлення, його можна підняти командою `sudo systemctl start ip-media-tool-runtime ip-media-tool`. Ноди запускаються вручну з графа. Профіль і напрямки портів переглянь у Blackmagic Desktop Video та в панелі DeckLink. Перевір відповідність фізичних BNC обраним persistent ID, особливо якщо на сервері кілька плат. Команда `gst-inspect-1.0 decklinkvideosink` показує назви режимів GStreamer. Підтримку конкретного режиму звір із виявленими можливостями потрібного порту та з фактичним SDI lock.

## Фізичне підключення

```text
Генератор SDI → A · SDI Input ── SHM ──→ B · SDI Output
                                         │
                                     кабель SDI
                                         ↓
                                      C · SDI Input
```

1. Задай на генераторі чорне зображення з коротким білим спалахом у центрі та одночасним аудіоімпульсом на першому embedded каналі. Повторюй раз на секунду. Тривалість спалаху має становити щонайменше два кадри повільнішої ділянки, пауза між імпульсами щонайменше 0,5 с. На першому каналі між імпульсами має бути тиша, пік імпульсу має перевищувати −12 дБFS. Для початкового проходу використовуй UYVY або v210.
2. На графі створи **A** як SDI Input, **B** як SDI Output, **C** як SDI Input. Обери три різні ID. Для **A** і **C** вибери однаковий PCM і ввімкни **Вимірювати A/V за спалахом та імпульсом**. Від порту **A** проведи ребро до **B**. **C** читає сигнал із фізичного кабелю.
3. Для **B** встанови `1080p25`, `UYVY` та 100 мс. Запусти **B** першим і перевір стан «Очікує джерело». Запусти **A** і **C** та дочекайся стану «Працює» на всіх трьох. За відсутності capability snapshot повтори детекцію з панелі DeckLink.
4. Візьми три UUID з конфігів нод у `/etc/ip-media-tool/nodes/`. Поле `name` дозволяє ідентифікувати кожну ноду. Запусти у вказаному порядку **A**, **B**, **C**:

```bash
cd /opt/ip-media-tool/current
sudo -u ip-media-tool env PYTHONPATH="$PWD/src" PYTHONDONTWRITEBYTECODE=1 \
  /usr/bin/python3 tests/linux_sdi_acceptance.py UUID_A UUID_B UUID_C --fps 25
```

Сценарій читає статуси і збирає щонайменше 30 нових пар міток на кожному вході у двох послідовних вікнах. Позитивний `audio_minus_video_ms` означає, що аудіо запізнюється. Допуск для середнього доданого зсуву в кожному вікні та зміни між вікнами становить один кадр повільнішої ділянки (40 мс при 25 кадрах/с). Під час вимірювання лічильники розривів на вході, SHM-пропусків і запізнілих буферів мають стояти на місці. Для витримки із щосекундними мітками додай `--pairs 600 --timeout 720`. Для 1080i50 передай `--fps 25`, для 1080i59.94 — `--fps 30000/1001`. Вимірювання контролює синхронізацію аудіо та відео в межах кадрової точності. Для абсолютної затримки маршруту та перевірки окремих полів використай зовнішній аналізатор.

## Додаткові проходи

- Від'єднай генератор від **A**. **A** має перейти в «Очікує сигнал», **B** в «Очікує джерело». Поверни кабель і дочекайся нового покоління без ручного перезапуску. На **C** має відновитися зображення та звук. Повтори команду вимірювання.
- Перевір зміни 1080p25 → 720p50, 1080p50 → 1080i50 та 1080i50 → 1080p50, якщо порти підтримують ці режими. Перевір роздільність і cadence на приймачі. Для interlaced сигналу перевір порядок полів на рухомій діагоналі чи за аналізатором. Після зміни параметрів повтори вимірювання з частотою повільнішої ділянки.
- Налаштуй 8 або 16 каналів на **A** і **C**. По черзі подай контрольний тон на кожен embedded канал і перевір його позицію на приймачі. Окремо виміряй A/V на першому каналі. Збережи модель плати, профіль, persistent ID, драйвер, версію GStreamer, режим, глибину PCM і результат.
- Зупини **B** на графі. Лічильники **A** мають далі зростати. Запусти **B** і перевір повторне підключення до того самого джерела. Після перевірки зупини три тестові ноди, якщо маршрут більше не потрібен.

У графі адміністратор або оператор може відкрити **Журнал** на картці ноди. Там видно запити запуску, відмови preflight, зміни стану, помилки воркера й повторні спроби. Журнал у браузері показує останні події від поточного запуску runtime. Історію systemd на Ubuntu можна прочитати окремо.

```bash
sudo journalctl -u ip-media-tool-runtime -u ip-media-tool -b -n 150 --no-pager
df -h /run
```

Щоб побачити помилку в момент запуску SDI Input, виконай `sudo journalctl -u ip-media-tool-runtime -b -f -o cat`, потім натисни **Запустити** в графі.

Якщо попередня версія повертала `Worker launch failed (FileNotFoundError)` до створення процесу, після оновлення перевір `systemctl show ip-media-tool-runtime -p PrivateTmp`. Очікуване значення — `PrivateTmp=yes`. Runtime використовує приватний тимчасовий каталог для перевірок GStreamer і DeckLink. Помилки запуску містять етап, а системний журнал — також тип винятку, errno та місце у коді.

Вихід працює з одним embedded PCM-банком 48 кГц і 2, 8 або 16 каналами. SHM переносить сире відео й PCM. SDI ANC, RP188, субтитри та HDR side data поза межами цього маршруту. Точні режими, пропуски і довготривалий drift підтверджуються окремо на кожній комбінації обладнання та формату.
